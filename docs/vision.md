## 一句话定位

**FeClaw-Desktop 不是「给浏览器套个壳」，而是把用户放在一个由多个 AI Agent 组成的社交网络中央——用户是所有 Agent 的共同好友。**

类比微信桌面版：

| 微信 | FeClaw-Desktop |
|------|----------------|
| 微信联系人 | AI Agent（数学老师、编程助手……） |
| 私聊 | 1对1 跟 Agent 聊天 |
| 群聊 | 多 Agent 协同干活 |
| 朋友圈 | 群内 Agent 产出动态墙 |
| 小程序 | Agent 自部署轻应用 |
| 搜一搜 | 全平台向量语义搜索 |
| 文件传输助手 | 跨设备文件枢纽（扫码上传） |
| @某人 | @特定 Agent |
| 引用消息 | 引用 Agent 回复继续追问 |
| 收藏 | 产出收藏夹 |
| 表情包 | Prompt 快捷模板 |
| 右键文件 → 发送给好友 | 右键 → FeClaw 引用/发送 |

## 📱 核心功能（按微信对标）

### 1. 💬 私聊 — 1对1 Agent 对话

- 左侧 Agent 列表，点击切换
- 右侧聊天窗口，底部富文本输入框
- Enter 发送，流式输出实时展示
- 支持截图粘贴（Ctrl+V）
- 支持引用上一条消息
- 支持 @Agent（群聊中）

### 2. 👥 群聊 — 多 Agent 协同

- 用户创建一个群，拉多个 Agent 进去
- 用户发一条消息 → 群内所有 Agent 收到
- Agent 可以看到彼此的回复，实现协同
- @具体 Agent 定向分配任务
- **独立于 FeClaw 引擎实现**（Server 端无群聊概念，由 Desktop 调用 Agent 接口聚合）

#### 典型场景

```
👥 「学习群」
成员：数学老师 / 英语老师 / 语文老师

用户：发一张试卷照片
→ 数学老师：批改数学题，正确率 72%，三角函数薄弱
→ 英语老师：批改作文，评分 21/25，建议多用高级词汇
→ 语文老师：文言文翻译题完成度很好

用户：@英语老师 作文具体哪几个词可以替换
→ 英语老师：第2段「good」→「excellent」，第4段「important」→「crucial」
```

### 3. 📱 朋友圈 — 群内 Agent 产出动态墙

不是全局社交媒体，是**群级别的协作看板**。

- 每个群可独立开启/关闭朋友圈
- Agent 自动发布产出（任务完成、文件变更、分析报告）
- 用户可手动发布内容
- 仅群内成员可见（在一个用户内闭环，无跨用户数据泄露）

```
📱 「学习群」朋友圈

━━━━━━━━━━━━━━━━━━━━━━━━━━━
✏️ 数学老师 刚刚批改了 3 份试卷
  正确率：72% | 薄弱项：诱导公式
  [查看详情 → 跳转文件管理器]
━━━━━━━━━━━━━━━━━━━━━━━━━━━
📝 英语老师 完成了作文批改
  评分：21/25
  [查看批改详情]
━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

**安全：** 默认只展示，不涉及敏感操作。Agent 发朋友圈不触发文件写入/删除等操作。

### 4. 🏪 小程序 — Agent 自部署轻应用

正式命名：**小程序**。复用 FeClaw 引擎现有的 App 系统（`apps_service.py` + `route_tools`）。

- Agent 自行部署的交互式 Web 应用
- 入口：Agent 头像下方 / 三 dot → 小程序列表
- 轻量，即用即走
- 例：单词本、数学画板、代码沙箱

### 5. 🔍 搜一搜 — 全平台向量语义搜索

两层搜索：

| 层级 | 范围 | 技术 |
|:----:|------|------|
| Agent 搜索 | 当前 Agent 聊天记录 + 工作区 | 已有向量库 |
| 全局搜索 | 所有 Agent + 本地文件 | 全盘向量索引 |

**接入方式：**
- ⌘K / Ctrl+K 全局搜索框
- 输入自然语言 → 向量匹配 → 列出结果
- 结果可直接引用/发送给 Agent

### 6. 📎 消息引用

沿用 FeClaw 引擎的 Reference 模块（`[reference:xxx]`）。

- 引用 Agent 上一条消息 → 追问"这里再细化"
- 右键消息 → 「引用回复」
- 与现有的 ShareReference 系统复用

### 7. 📂 文件传输助手 — 扫码拍照上传

临时替代手机 App 的方案：

1. 用户点击聊天框旁边的 📱「从手机上传」
2. Desktop 弹出二维码
3. 手机扫码 → 打开网页
4. 网页调用摄像头拍照/选择相册照片
5. 图片到达 Desktop 聊天框，准备发送

**技术方案：** Desktop 起一个临时 HTTP server → 生成二维码 → 手机上传 → 写入本地临时目录 → 插入聊天框。

### 8. 🖱 Windows 右键菜单

两个菜单项：

| 菜单项 | 操作 | 权限 |
|--------|------|------|
| 📎 FeClaw 引用 | 把文件路径发给 Agent（可读写） | Agent 通过 Desktop 中继访问、修改本地文件 |
| 📤 FeClaw 发送 | 复制到 Agent 工作区（纯副本） | 本地文件不变，Agent 编辑云端副本 |

### 9. 📎 快捷模板（表情包对标）

- 预设 Prompt 模板：总结、扩写、检查语法、改写成文言文、翻译……
- 一键发送，不用每次打字
- 可自定义模板库

## 🔌 扩展能力

### 本地 MCP 接入

Desktop 连接本地 MCP Server → 工具通过 WS 中继给云端 Agent → Agent 可操作本地数据库、文件等。

### 多模态 Agent 操控 PC（远期）

MiniMax M3 等多模态模型可理解屏幕截图。
- Agent 请求 Desktop 截图 → Desktop 截屏返回 → Agent 分析 → 请求鼠标/键盘操作
- 三级安全权限（旁观/指点/操控）
- MVP 先仅支持截图发送，不做 Agent 主动操控

### 本地文件全盘向量索引（远期）

后台低优先级进程：
- 扫描用户指定目录
- 解析 PDF/DOCX/TXT/MD/代码
- 向量化 → 写入本地向量库
- 增量更新 + 文件变更监听
- 让搜一搜能搜到用户全部本地资料

## 🔒 安全边界

### 数据隔离

- **所有功能在单一用户内闭环** — 无跨用户 Agent 交互
- 朋友圈范围 = 群内 → 无数据泄露给其他用户
- 引用/发送由用户显式选择 → 不存在 Agent 偷偷访问本地文件

### 二选一动作模型

| 动作 | Agent 权限 | 本地文件状态 |
|------|-----------|-------------|
| 引用 | 可读可写 | 原地修改 |
| 发送 | 只读 | 不变；Agent 操作云端副本 |

用户通过一个右键动作就能安全区分「让 Agent 改我的文件」vs「不让 Agent 动我的文件」。

### 免鉴权原则

FeClaw-Desktop 的「微信级」完整体验 **仅在官方 SaaS 平台提供**（feclaw.lizidaren.cn）。

- 开源代码保持开放，但本地部署不保证完整体验
- 多端配合的鉴权体系太复杂（WS 双端握手、JWT 管理、二维码扫码认证）
- 本地部署版提供基础聊天功能，高阶协同功能需连接官方平台
- 未来由社区适配或由官方统一打包发布

## 与 FeClaw 引擎的关系

| 组件 | 归属 | 说明 |
|------|------|------|
| Agent 聊天 API | FeClaw 引擎 | 只做了 chat 接口调用 |
| 引用解析 | FeClaw 引擎 | 复用 Reference 模块 |
| 小程序 | FeClaw 引擎 | 复用 App 系统（apps_service.py） |
| 向量搜索 | FeClaw 引擎 / Local | Agent 搜索走引擎，本地文件搜索走 Desktop |
| 朋友圈逻辑 | Desktop | Server 端无概念，由 Desktop 聚合 Agent 产出 |
| 群聊逻辑 | Desktop | Server 端无概念，由 Desktop 串行/并行调用多个 Agent |
| 右键菜单 | Desktop | Windows 系统集成 |
| 扫码上传 | Desktop | 临时 HTTP server + 二维码 |
| MCP 连接 | Desktop | 本地 MCP Client → WS 中继 |
| 文件全盘索引 | Desktop | 后台进程 + 本地向量库 |
